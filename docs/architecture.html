Data Flow

User changes a filter in FilterBar.vue (Time Period, Warehouse, Category, or Order Status), or navigates to a view.

↓

Singleton filter state updates. useFilters.js holds module-level refs shared by the FilterBar and every view — one source of truth, no store library.

↓

Views react via watch() on the refs they care about and call api.*(getCurrentFilters()), which maps UI names to API params (location → warehouse, period → month).

↓

api.js issues an axios GET to http://localhost:8001/api/..., building URLSearchParams and omitting any filter set to 'all'.

↓

FastAPI filters in memory. apply_filters() and filter_by_month() run list comprehensions over module-level lists loaded once from server/data/*.json; quarters (Q1–Q4 2025) expand to month prefixes.

↓

Pydantic validates the response where a response_model is set, and JSON is returned (CORS allows all origins).

↓

Views store raw data in refs (allOrders, inventoryItems, …) and derive chart data, tables, and KPI totals in computed properties; templates re-render SVG charts and tables.

Notable Observations

  • gap api.js defines tasks (/api/tasks) and purchase-order functions with no matching backend endpoints; the server's PurchaseOrder models are unused.
  • gap Backlog.vue exists but is not registered in the router — backlog data is surfaced inside the Dashboard instead.
  • quirk Reports.vue bypasses api.js and calls axios directly; it ignores the global filters.
  • note Inventory has no time dimension, so the Time Period filter does not apply to it.
  • note Revenue goals are hardcoded conventions: $800K/month for a single month, $9.6M YTD across all months.
  • note i18n supports English and Japanese; currency display switches USD/JPY at a fixed rate of 150.
